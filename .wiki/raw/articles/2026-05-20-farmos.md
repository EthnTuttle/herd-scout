# farmOS

- License: GPL-2.0
- Stack: PHP / Drupal 10 backend; REST/JSON:API
- Stars: ~1.3k
- Status: actively maintained; release 3.5.2 ~Apr 2026

## What it is

The de-facto open-source farm management information system (FMIS). Records crops, livestock, equipment, soil, sensors, and observations on a Drupal-based platform with a Leaflet/GeoJSON map UI, pluggable modules, and a JSON:API. Hosted offering by Farmier; many self-hosters.

## Data model (canonical)

Five primitives — adopt this design directly or stay API-compatible:

1. **Assets** — Land, Plant, Animal, Equipment, Compost, Structure, Sensor, Water, Material, Product, **Group**. Group is a container for other assets — the elegant way to model herds/mobs.
2. **Logs** — Activity, Observation, Input, Harvest, Lab Test, Maintenance, Medical, Seeding, Transplanting, Birth, Movement, Purchase, Sale.
3. **Quantities** — attached to logs; inventory is *derived* (sum of increments minus decrements since last reset, per measure+unit).
4. **Terms** — taxonomy vocabulary (crop varieties, animal types, units, etc.).
5. **Plans** — sequences of activities/expectations.

## Mobile + desktop story

- **Desktop**: web only (self-host or hosted).
- **Mobile**: Field Kit PWA (Vue, offline-first) syncs to farmOS server. No native iOS/Android. Field Kit last release Apr 2023 (2.0.0-beta.2) — maintained but slow-moving.

## Strengths

- Mature data model, JSON:API, real ecosystem
- Active community (farmos.discourse.group)
- Module/plugin system enables vertical extensions

## Weaknesses (gaps for herd-scout)

- Drupal/PHP stack is heavy for ranchers wanting fast offline mobile-first tools
- No native EID (RFID) tag reader integration
- No drone orthomosaic / NDVI ingestion in core; farmOS-map supports only WMS/XYZ/GeoJSON, not GeoTIFF/COG natively
- Vegetation indices remain backdrop layers — *not queryable per-field attributes*
- Financial rollups (per-herd / per-field P&L) punt to QuickBooks export

## Why it's worth ingesting

farmOS is the gravity well of OSS farm management. Anything new should either build on top of it (modules, JSON:API consumer, complementary mobile client) or stay data-compatible. The Asset+Log+Quantity+Term+Plan model is well-designed and extensible.
